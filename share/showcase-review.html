“What you can build” — simplifying the template cards

A pass over the showcase cards in PR #491, aimed at the note in the original ask: the mock-up has a lot going on, and the elements compete for attention.

stackblitz/bolt-help-center #491 Home page + Templates page Screenshots are the four live templates from the branch

What’s competing

Each card carries five separately-styled elements: a bold title, a blue uppercase category link, a gray blurb, a filled blue “Live preview” button, and a second gray “or see it in the marketplace” link. That’s three different link treatments per card, so the four-card grid puts sixteen clickable things in one section. The blue button is the loudest element, but it repeats identically four times, so it stops signalling anything.

The other issue is that the cards don’t borrow from the template detail page they lead to. The marketplace already has a card vocabulary — mint category eyebrow, white title, gray description, paired buttons — and matching it makes the docs feel like the same product.

What changed, and why

ElementChange
Category Blue link → mint Silkscreen eyebrow, matching .detail-category. It was a link competing with the CTA; as a label it just orients you.
Card surface Loose image with text beneath → one contained card with a hairline border, so each template reads as a single object.
Actions Button + text link → two real buttons in a 50/50 grid: blue Live Preview, outlined All Templates. Mirrors the detail page’s stacked pair.
Alignment Buttons sit in a margin-top: auto row so they bottom-align across cards regardless of blurb length.
Radius 8px → 2px on buttons, card, and image frame, per the house standard.
Title 15px → 17px, so it leads the card rather than tying with the button.

Where the values came from

Not eyeballed — pulled from the live template detail page stylesheet (/public-page-assets/astro/_slug_.*.css), so the docs cards and the marketplace stay in step.

.detail-category {
  font-family: Silkscreen, monospace;
  font-size: 11px;
  letter-spacing: 1.5px;
  text-transform: uppercase;
  color: #7fddc1;
}

#7fddc1 is a real system color, not a one-off: the same detail page uses it for .hero-pills, .inline-link, the active catalog filter, and the “Sign up free” link, with #a5ebd8 as the hover state. The face is Silkscreen, the pixel font — not Inter at weight 600, which is what an eyeballed copy would land on.

That page lives in bolt-public-pages as an Astro [slug] route, so when this ships for real those class names and values can be copied rather than approximated.

Also found in the PR

Separate from the visual pass — three things worth fixing before merge.

Blocker

The Templates page isn’t in the nav

use-cases/templates.mdx is added, but the branch’s docs.json has no use-cases/templates entry. Mintlify won’t show it in the sidebar, so the page ships orphaned.

Stale

The crop-ratio comment describes screenshots that are gone

It says SocialPulse (1.108) sets the floor for LIST_RATIO, but SocialPulse and Kern were swapped for La Lumière and Nexal. Measured from the current four: Ledger is now widest at 0.995 (Maison 0.891, La Lumière 0.646, Nexal 0.590). Nothing breaks — 9/8 still clears it — but by the comment’s own logic the ratio could drop to 1 / 1 and show more of each page.

Cleanup

templates-showcase.mdx.delete-me should be deleted

It imports ShowcaseCard, ShowcaseList, which the component no longer exports, and its TODO placeholders are all resolved. Harmless, but it’s 60 dead lines in the merge.

Note

The list layout doesn’t stack on phones

The layout="list" variant used on the Templates page is a two-column inline grid with no media query, so it stays side-by-side on small screens. Inline styles can’t carry breakpoints — it needs a class in styles.css, the same workaround the PR already uses for backgrounds.

Scope

docs.json also drops the “Switch to Bolt Agent” group

The page building/switch-v1-projects.mdx still exists on the branch. Probably intentional, but it’s unrelated to this PR and deserves a line in the description.

One open question

“All Templates” reads as the marketplace index, not this template’s own page — so in the mock-up it points at the listing. That makes the section’s footer link redundant, since all four cards now share one destination.

Option 1: keep it pointing at the marketplace and drop the footer link. Tighter, but you lose the path to each template’s detail page, which is where Use Template actually lives.

Option 2: point it at the individual template and relabel it “Get Template.” The footer link stays meaningful as the one “see everything” exit, and it mirrors the detail page’s own button pair.

Leaning toward option 2 — the job of the card is to move someone toward that template.
